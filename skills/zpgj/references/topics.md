# 选题构思、评分与筛选

适用于所有行业。优先使用现有录音、访谈、IP 素材和已整理的可靠资料。
固定顺序：**具体内容＋观看理由＋补充 → 一遍能懂的标题 → 评分与筛选。**
用户只要选题时，交付到选题；需要框架时给框架，不提前写完整脚本。

## 1. 确认本轮交付与数量

先从当前请求读取账号、目标、受众、题型、最终数量和限制。
N 表示候选数量，M 表示最终入选数量；按当次要求变化，不固定某组数字。
用户明确“N 选 M”时照做；“给我 4 条”通常指最终交付 4 条，不擅自变成 4 选 1。
用户只指定 M 而要求筛选机制时，合理确定候选池，并在交付中说明本轮 N 与 M。
如果数量或题型表述存在真正冲突，集中澄清；已有明确要求不重复问。
不能为了凑 N 补编经历，也不能为了凑 M 降低来源要求；不足时交付已有可靠题并说明缺口。

对每个候选先检查：符合当前账号目标、目标观众有具体处境、与人物或行业有关。
题材可以来自工作、家庭、人情、消费或经营选择，不能只围绕行业术语换标题。
多元化看内容与观看收获是否不同，不是给同一问题换人物、商品或数字。

## 2. 每个候选先写公式

| 栏目 | 要回答的问题 | 常见错误 |
|---|---|---|
| 具体内容 | 到底讲哪件事、哪个问题、哪次选择或哪个判断？ | 只写“分享经验”“避坑”，没有内容 |
| 观看理由 | 这位观众为什么想看？想知道后续，还是要解决什么？ | 只写“有共鸣”“反差大”，没有观众动机 |
| 补充 | 哪些动作、原话、场景、凭据、条件或演示让内容讲得清楚？ | 补编人物心理、过程或结果来制造冲突 |

具体内容是主线；观看理由来自真实兴趣或实际需求；补充用于讲清和兑现。
三项相互对应，不能先想夸张标题，再往三个栏目里填套话。
补充的信息需要有来源；未知的数字和结果写待核，不能被标题偷偷确定下来。

可使用下列构思卡，先写内容再拟题：

```markdown
编号：
题型：叙事 / 解决问题
具体内容：
观看理由：
补充：
素材来源与位置：
来源性质：本人材料 / 公开资料 / 演示算例 / 经授权的创作设定
缺失或待核项：
选题主体（标题）：
```

普通演示算例必须注明演示条件；创作完整人物故事需要用户明确授权并标注创作设定。
有情境构思不等于发生过；本人一句观点，也不足以支撑一个完整客户故事。

## 3. 标题先过“一遍懂”这一关

临时隐藏公式和来源说明，只看标题：目标观众能否说出发生了什么或能解决什么？
叙事题应看懂人物的处境、动作或变化；解答题应看懂问题和观看收获。
不必每题塞满人物、时间和地点，但不能依赖正文解释行话、代词或抽象概念。
只留下“真相”“震惊”“你一定不知道”等词，不能当成内容清楚。
不理解就先改标题，改后重看；不要用补充说明替标题过关。

结构演示：

- 不清楚：客户的认知差影响了转化。
- 较清楚：客户一直问最低价，店员先问清他准备怎么用。

这是表达结构示例，不是任何账号的真实经历或自动适用选题。

## 4. 五项各 0–2 分，总分 10 分

评分用于本批候选的内部比较，是助手判断；不是爆款概率、播放量预测或事实认证。
不预设入选题必须几分，不为了凑出“最高分”人为抬分。
先基于观众能看到的标题评分，再独立检查公式、素材与正文能否兑现。
不能用标题里没有的解释、隐藏故事或拍摄想象补救标题分数。

下表是统一打分口径：

| 项目 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 真实感 | 处境明显不自然或靠虚构夸张成立 | 处境可理解，但较抽象或安排感较强 | 场景、动作或选择自然，观众容易相信会发生 |
| 可信反差 | 无有效反差，或冲突牵强 | 差异成立，但常见或力度较弱 | 预期与实际、两种需要或选择形成自然且清楚的差异 |
| 想看 | 看完标题仍不知道为什么要看 | 有一定疑问或收获，但后续吸引较弱 | 有明确后续兴趣，或看得见值得获取的解决办法 |
| 代入 | 与当前目标受众的处境关系弱 | 只触及其中一部分人或特定情境 | 目标受众能直接对照自己的问题、顾虑或选择 |
| 表达 | 难懂、歧义或主要依赖行话 | 能懂，但冗长、抽象或有多余信息 | 一遍能懂，主体与动作清楚，口语容易表达 |

“真实感 2 分”不证明是真实案例；来源真实性必须另查。
“代入”相对于本轮目标受众评分，不把小众精准题必然判低分。
解答题可以直接给结果，不必为了悬念隐藏方法；观看价值可来自实际收获。
保留五项分与总分，说明扣在哪；不能只写“很好”“冲突强”。
如展示得分比例，只能称自评得分比例，不能称成功率。

## 5. 先看能否入选，再按分数和要求筛选

标题分数与素材可写程度分别记录。高分不能替代来源、完整经过或可执行方法。
出现以下情况时暂不入选，并说清补什么才能继续：

- 关键事实、人物身份或结局没有依据；把别人的经历当成 IP 亲历。
- 叙事缺少真实可用的推进过程，只能靠补编人物、动机或结果讲下去。
- 解答只剩提醒和态度，没有可以执行的动作，或结论超出资料适用范围。
- 与账号当前目标明显不符，或违反用户已经明确的内容边界。

在可入选候选中按总分排序。用户指定题型配额时分组排序，例如两类各取指定数量。
不指定配额时不强行一半故事、一半解答；不要用整体排名掩盖分组筛选。
同分时说明具体取舍：来源更充分、目标更匹配、观看收获更明确、表达更清楚或与其他题更不同。
若低分题因去重或题型要求入选而高分题落选，必须解释，不能宣称是全池最高分。

核心去重比较“问题或人物处境—主要矛盾—观看收获或结论”。
换称呼、数字、案例外壳或同义标题，核心仍相同的题合并或淘汰。
相邻话题可以保留，但要说清它们解决的不同问题，不能只说标题不同。
旧题资料不可得时如实标注查重范围，不声称已经查遍历史。

## 6. 逐条说明筛选，展开入选题

候选公式表：`编号 | 题型 | 具体内容 | 观看理由 | 补充 | 来源`。
评分取舍表：`编号 | 选题主体 | 五项分 | 总分 | 入选/淘汰 | 依据与扣分点`。
每一条入选和淘汰都说明原因，同分题写明保留谁、为什么。
公式与评分表可按批次拆开，避免一张过宽表；编号始终对应。

入选题按用户要的格式展开，默认包含：

```markdown
选题主体：
具体内容：
观看理由：
补充：
五项分与总分：
入选理由与扣分点：
素材依据与待核项：
```

用户要求框架时，按题型分别写：

- **叙事框架**：人物处境 → 发生的事与选择 → 变化或转折 → 已知结果 → IP 可表达的判断。
- **解答框架**：具体问题 → 判断条件 → 做什么、怎么做 → 怎样核对结果 → 方法的适用边界。

叙事靠行动和选择体现人设，不硬插自夸；解答给实际办法，不硬改成故事。
框架标清缺失事实，不替公开案例补结局；用户只要选题时不扩写成逐字稿。
