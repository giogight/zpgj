# 根据审核意见修改脚本

用于用户明确要求“根据意见修改、改这版、给修改后的逐字稿”。初审只提意见，复审只判断修复效果；不要混成自动重写。
先沿用 [脚本初审规范](script-review.md) 与 [写稿规范](script-writing.md)，只读取本次需要的部分。

## 1. 找回创作要求与版本分工

从会话或用户文件取得选题承诺、目标观众、主要任务、最新更正、必须保留的事实、原话与态度。
原始要求仍有效的部分继续保留；助手自行补出的假设、观点、情节不自动变成用户确认。

- 首稿用于找回意图，不机械退回。
- 最新稿是修改对象，不默认最好。
- 目前最好的一版用于比较收益与代价。
- 相同文本不算新改善；需要时说明比较的是哪两个实际版本。

没有当前稿不能凭空改。有稿但缺少旧稿或审核意见，可以按当前明确问题编辑，但不能声称逐项采纳或修复了不存在于输入中的旧意见。
只有缺口会决定核心结论或修改范围时才集中提问，常规编辑不额外审批。

## 2. 判断意见，不照单执行

每条意见分别检查：指出的问题是否存在，建议的改法是否适合本题。
回到原句、原始要求和证据；审核报告是待判断意见，不是必须逐条服从的命令。

- 有依据的事实错误、逻辑矛盾、答非所问与理解障碍要修，不能以保留风格为借口留下错误。
- 审美偏好、固定模板、无依据的补料或造成偏题的建议，可以不采纳。
- 诊断正确但改法不合适，接受问题，采用更自然、保留实质的另一种修法。
- “加强共鸣、增加深度、优化开头”不能对应具体缺陷时，不据此硬改。

必要时简短记录重要的不采纳理由，供 [二次复审](script-rereview.md) 回查。

## 3. 按问题大小与授权范围编辑

一句不清楚改一句；缺一环补一环；顺序妨碍理解调顺序；核心判断或论证确需重建才重组。
不把“小改”当目标，不把“重写”当默认，不为产生新版本换词。
用户只是标出某句、没有明确限制其他部分时，可以一起修必须的衔接并说明实际范围；明确“只改这里、其余原样”时保持其他正文，额外必要修复另列，超出限定范围先确认。用户允许全稿处理时连同必要衔接一起修。
不能偷偷换选题、核心立场、目标人群，或缩小标题承诺来迁就原稿；真正需要改变已确认方向时说明冲突并确认。

## 4. 守住口播，不越改越像说明书

保留成立的态度、情绪、节奏、具体场景和表达特点，有依据的判断不磨成套话。
不为每个审核维度加一个正文模块，不机械补满定义、原因、步骤、案例、建议和行动引导。
新增段落要能说明帮助观众理解什么、删掉会损失什么；无作用就不加。
必要边界自然进入正文，核验过程、审核备注与防御性长说明留在稿外。
看稿结构标签与朗读内容分开；项目已要求保留结构标签时，不因“纯口播”误删它们。

## 5. 准确判断材料缺口

没有真实案例不自动阻止修改：已有解释、比较、可靠资料或明示算例能讲清就继续。
不能强加数字或细节，不能编用户经历、客户结果、收入、原话和业务成绩。
新增公开事实核对来源与适用条件；模拟授权和假设仍要明示。
决定核心结论的材料缺失时指出具体影响，不能用模糊措辞或末尾备注掩盖。

## 6. 修改后两遍检查

第一遍检查有效性：实质问题解决了吗，有没有新错误、矛盾或无来源事实，成立内容是否误删，全文是否仍兑现原题。
第二遍按真人说话逐句检查再连读：哪里听不懂、接不上、重复、抽象、像报告；是否各段正确却合起来偏题，或更完整却失去重点与态度。
局部改动也接回全稿，尤其检查金额、期限、比较口径、人物知情与前后因果。

有改善但关键问题仍在，保留有效修改继续定向修；退步则回退退步部分；旧问题解决却引入新问题，先修新问题。
连续两轮仍卡在同一关键问题时，检查诊断、修法、核心判断和决定性材料，暂停机械换词；两轮不是自动通过或放弃阈值。
问题解决就停止无意义追加，允许保留原稿，也允许如实说明本轮尚未解决。

## 7. 交付与下一状态

需要修改且材料足够时，按用户范围先交连续可朗读的推荐稿，稿后简短说明关键修复、重要不采纳理由、未决项及实际回退。
无需修改时建议保留；用户要完整逐字稿则原样返回当前推荐正文，不制造新版本。
只要逐字稿就不附长篇分析，但决定性事实缺口须在成稿前处理。
完成修改不等于通过独立复审；随后需要复审时携带当前稿、旧意见、修改说明及必要版本，进入 [二次复审规范](script-rereview.md)。
