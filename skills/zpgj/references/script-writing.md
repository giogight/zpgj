# 写稿与明确授权的改稿

选题确定后需要写逐字稿，或用户明确要求修改现有稿件时，使用本参考。
只有“审核、看看、给修改意见”时，先使用 [script-review.md](script-review.md)，不要自行重写。

## 1. 找回本条任务

先从已有对话和材料提取，不重新做完整背景访谈：

- 讲给谁听，他们眼前遇到什么事。
- 选题、标题或开头承诺了什么；本条主要交付答案、观点、故事、体验还是信任。
- 用户已确认的核心判断、表达态度和必须保留的事实或原话。
- 业务边界、内容形式、篇幅、拍摄状态及本轮修改范围。

缺少会改变核心结论的信息时，集中问少数关键问题，最多五个，能少问就少问；不要求每轮凑满数量。
材料足够就继续成稿，不增加“现在可以写吗”的形式审批。
用户允许直接推进时，说明必要假设；假设不能变成经历、规则或效果事实。
内容类型帮助选择展开方式，不替代材料，也不构成必须逐段完成的模板。

## 2. 选题之后、写稿之前：判断答案与规则

| 选题性质 | 写前要完成什么 |
| --- | --- |
| 有确定答案 | 核实答案、依据及适用条件；计算题先明确口径并算准结果。 |
| 有明确规则，但个人选择不同 | 查清共同规则和变化因素，再结合实际条件给出判断依据。 |
| 叙事、经历或观点，没有统一答案 | 沿材料和已确认意图展开，不硬凑数字、标准结论或解决方案。 |

有规则不等于所有人都应作同一个选择；不能用“因人而异”回避已经能回答的部分。
混合题分别处理：先讲能确定的规则，再说明哪些变量影响选择。
故事或观点中出现可查证主张，也要核实该主张，不能因类型不同跳过事实判断。

必要核实时优先查用户已有材料和可靠原文；按任务需要核对官方规则、合同、公示或研究。
记录来源、日期、适用对象、产品或地区；旧资料和其他人的条件不能直接套用。
没有实际查证，不称“已核实”；没有足够依据，不编统一规则或固定结果。
决定核心结论的依据仍缺时，补关键缺口，不能用“以实际为准”掩盖错误。
写前形成简短内部结论：答案类别、依据、确定结果、待核算项、个人变量及观众能带走什么。
按用户需要展示这一结论；核验记录与完整分析留在稿外。
规则题写前确定一项观众以后能用于核对、计算或比较的具体成果，例如准确结果、费用差别、判断依据或可执行步骤；不以泛泛提醒或“记得收藏”替代收藏价值。

## 3. 给材料分层，确定能写到哪里

| 材料性质 | 使用边界 |
| --- | --- |
| 已核实的公开事实 | 按来源能支持的程度表达，保留会改变理解的时间和适用边界。 |
| 作者观点 | 明确是判断或立场，给出相应理由，不伪装成客观定律。 |
| 本人或他人口述经历 | 保留自述来源；未经独立确认时，不称已经证实。 |
| 用户给定的策划情境 | 是创作问题或约束，不自动证明事件发生，也不自动授权编造经历。 |
| 授权的模拟故事、条件算例 | 明确为模拟或假设，只承担说明作用，不冒充亲历、新闻或效果证据。 |
| 未知、缺失或未经核实的内容 | 说明缺口及影响，不补成确定事实。 |

不拼接不同案例冒充同一事件，不新增真实人物的对话、心理、金额、因果或结果。
用户明确要求编模拟故事时，可以在本次授权范围内创作，不反复索取同一授权。
模拟授权不自动延伸到后续其他选题；模拟情节也不能证明行业规律。
没有真实故事材料时，可用已有解释、对比、公开资料或明确假设讲清问题，不强求客户案例。
涉及实际价格、费用或金额时，分清报价、历史数据与演示条件，假设金额不能当实际报价。

## 4. 数字和比较先在内部完成

- 对齐比较对象、金额、观察或使用期限、发生时点及费用范围。
- 各对象的实际变化分别核算，不能拿初始状态代替整个期间。
- 区分已付、已产生但未付、未来可能发生的成本，以及剩余义务或余额。
- 涉及借还款时，另分本金、已归还本金、费用与未还本金；本金不等于借款费用。
- 同一期限内，一种方案结束、另一种仍有余额或义务时，必须交代这项差别。
- 现金当下付得少，不等于总成本低；可行性也不能只看一个收入或预算总数。
- 说明影响选择的真实约束，例如时间、生活开销、产能或剩余预算，不替用户补条件。
- 假设与简化要明示；日期、四舍五入等处理保持一致，结果只支持设定条件下的判断。

内部核算要充分，口播不必念完整计算记录。
观众只问结果，就集中讲必要结果、差额、剩余义务及关键条件。
观众需要学会算法，才展示足够复算的步骤；不要默认逐项逐期朗读。
数字集中成一个完整答案，不让听众在相邻段落拼余额、已付数和总额。
压缩表达前先验前提与可行性：短句不等于判断正确。

## 5. 用内容任务组织正文

默认可用 `【痛点】→【冲突】→【框架】→【共鸣】` 作为看稿标记，拍摄时不朗读。
用户指定其他结构、纯逐字稿或特定形式时，以该要求为准。
标记用于看清推进关系，不能为了填满四格机械添加内容；解决方案按题目需要，不固定加第五段。
用户沿用原单人 IP 项目规范时，读取 [原项目制作配置](../assets/source-project-profile.md)，保留约三分钟等已确认偏好；其他项目不自动继承。

- 痛点：用具体处境和眼前选择进入，让目标观众认出这件事与自己有关。
- 冲突：讲清人物已做什么、想做什么、被什么卡住，以及具体影响。
- 框架：承担主要交付；故事推进经过，解答给出答案与依据，观点展开理由和分歧。
- 共鸣：回应真实处境和代价，必要时收住态度；不强行升华、劝导或重复全文。

叙事按事件、知情、选择、变化和已知后果推进；不能开头有个人物，后面全变成建议。
冲突发生在事情中，不靠“你以为/其实”“表面/背后”的语言对仗制造。
项目要求单人 IP 口播时，由本人连续讲述、自然转述必要对话，不交角色表、场景切换、多角色轮流台词或镜头旁白脚本；用户明确要求剧情形式时另按该形式处理。
分清叙述者知道什么、人物当时知道什么；先后发生不自动构成因果。
补清关键原因也能推进故事，不靠无关动作、轮流对话或情绪总结凑经过。
解答围绕本题解释“为什么、怎样判断或怎么办”，不能用泛泛提醒代替答案。
标题已承诺处理办法时，讲有依据的具体判断、做法及其作用，不能只表态；标题未承诺方法时不强塞方法清单。
观点可以没有唯一答案，但立场与理由要对应；共情内容可以不提供解决方法。
这些形式可以混用，但次要任务不能挤走主要承诺。

## 6. 写成能说的话

先想清楚听众需要知道什么，再按真人讲这件事的语序写。
生活处境开头优先用时间、动作、对象和眼前困难，少用笼统心理概括代替内容。
其他内容若适合从结果、收益或悬念进入，不强制套痛点开头。
把动作和对象说完整；“处理一下”“安排一下”等省略不能让听众猜具体行为。
一句能讲清就一句讲清，但不把书面长句剪碎成不自然的短行。
少写“下面举个例子、我们来分析”等自我说明，直接进入必要例子和判断。
情绪优先体现在行为、顾虑和后果里；不是禁用所有情绪词。
前面已经说清的事，后面只在增加新原因、进展或影响时再提。
必要承接、留白与强调可以保留，不机械要求每句都有新事实。
专业和信任来自可理解的判断与行为，不靠术语堆叠或自夸。
不用比喻替代解释，不为押韵、对称写口号；样稿学习语气与语序，不照搬其中错误、冗长或未核实行业说法。
核验过程、审核备注与长篇免责声明放在稿外；决定理解的条件自然写进正文。

## 7. 明确要求改稿时再执行

完整修改判断与交付使用 [修改规范](script-revision.md)；修改后的二次审核使用 [复审规范](script-rereview.md)。以下是共同边界。
首稿用来找回意图，最新稿是修改对象；不要默认最新版最好，也不机械退回首稿。
审核报告是待判断的意见，分别核对“问题是否存在”和“建议改法是否适合”。
有依据的错误、矛盾和理解障碍要修；模板偏好或无效补料建议可以不采纳。
按问题决定范围：改一句、补一环、调顺序，或在确有必要时重组全文。
不为了产生新版本而换词；成立的观点、人物、因果、场景、口语和有效细节要保留。
需要改变已确认的受众、选题、核心立场或主要承诺时，说明冲突并确认关键选择。
常规删减、纠错与衔接调整直接执行，不为普通编辑反复审批。
局部修改后接回整稿，检查前后衔接、重复、指代、数字、期限和结论是否一致。
用户只是指出某句需要改、没有明确限定其他内容时，可一起修必须的衔接并说明范围；用户明确“只改这里、其余原样”时保持其他正文，额外必要修复另列，超出限定范围先确认。用户要全稿时交回接顺后的完整稿。

### 只改开头的快捷路径

不重做定位、不改变主线，也不顺手重写正文。
先确定原开头承诺与正文兑现范围，利用已有事实、立场、矛盾或结果写入口。
未拍或允许补拍时，给可以直接说的新开头，并接上原文下一句，检查连接是否自然。
已拍且不能补拍时，优先提出已有句段的裁剪或重排；缺少素材时不虚构可用镜头。
补录、字幕或画面建议须标明是新增制作动作，不冒充现有素材。
没有音画素材时，只能判断文本衔接与潜在理解障碍，不能断言精确划走秒数。
开头无法兑现时，指出缺口；改变承诺属于关键方向选择，不能偷偷换题。

## 8. 交付前连读两遍

第一遍检查答案、证据、条件、因果和比较是否成立，有没有引入新事实或误删有效内容。
第二遍按真人说话连读，检查接不上、指代不清、抽象、重复及突然转向。
局部都通顺不等于整稿兑现选题；纠错完成后停止无意义的追加润色。
出现反复改差时，撤回退步部分，保留有效纠错；无法解决的关键缺口如实说明。

默认交付完整、连续、能朗读的正文，结构标记与稿外说明分开。
只改开头时交付新开头与接续句；只要逐字稿时不附长篇分析。
必要时在稿后简短说明事实边界、改动范围或未决项，不逐条回应细枝末节。
篇幅与时长按用户要求及有效内容控制，不靠重复凑长；未试读只称估计，不能称实测。
用户要求实际 Markdown 文件时按指定位置保存，修订保留旧版并注明版本，写后重读；规范、具体素材和真实案例库分开，示例不自动登记为真实案例。
写完、通过文案审核、完成试读与获得实际传播结果是不同状态，不能混称完成验证。
