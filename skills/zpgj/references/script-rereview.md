# 脚本二次审核与复审

用于“复审这版、二次审核、检查改稿是否解决问题、复核上次意见”。沿用 [初审标准](script-review.md)，本轮重点是修复效果、版本比较和上一轮意见本身，不重新制造整篇问题。

## 1. 取得必要材料，确定比较基线

优先从会话或文件取得：原始创作要求与最新更正、当前稿及版本、上一轮审核意见、作者修改说明和重要不采纳理由、必要旧稿或目前最佳稿、事实资料及核验状态。
可用 [审核交接模板](../assets/review-handoff.md) 整理；没有的信息写未提供，不要求用户重复贴已有内容。

- 当前稿是复审对象，最佳稿是比较基线，首稿帮助找回意图，三者作用不同。
- 当前稿与最佳稿相同，明确“无文本差异”，不能把重复提交说成又改善一轮。
- 与确实不同的旧稿比较时，注明旧稿版本及具体变化。
- 缺旧意见或旧版仍可审核当前稿，但不能断言原问题已经修复或修改一定改善；指出缺口影响的是哪项比较。

## 2. 同时检查四件事

1. **旧问题**：原来成立的问题是否真的解决；用修改前后原句及具体影响验证，不只看有没有照搬建议。
2. **新问题**：是否引入事实错误、逻辑矛盾、理解障碍、过度省略或表达退步。
3. **原任务**：是否仍回答原问题，保留最新要求、已确认立场、人物因果和有效细节。
4. **版本收益**：相对明确的最佳版是改善、无实质变化还是退步；指出收益与代价。

事实正确不等于切题；每段单看正确也不等于整条有重点。故事、解答、观点与共情继续使用各自的任务标准。
保留必要承接、留白和重复强调，不能机械要求每句新增事实，也不能把合理解释删成空泛结论。

## 3. 复核上一轮审核意见

对重要旧意见重新问：问题有证据吗，问题性质判得对吗，建议的修法会不会失去答案、偏题或损伤表达？

- 作者没有照搬改法，不自动构成问题；其他方式已解决问题，就承认有效修复。
- 原意见无依据、模板化或过度，明确修正、降级为可选建议或撤回；不能为维护自己上一轮判断继续要求服从。
- 顺序优化不自动是唯一正确结构，措辞偏好不自动是事实/逻辑错误。
- 原诊断成立但原改法不适合，分别说明，给更小且保住实质的处理方向。
- 作者提出重要不采纳理由时对照原文判断；不能无条件接受，也不能当作不配合而忽略。

没有取得上一轮意见，就如实注明无法复核旧意见，不替上轮审核者编造观点。

## 4. 给出当前处理建议

允许零新增问题，不为凑数反复挑毛病。根据实际结果选择适用动作：

| 结果 | 处理 |
|---|---|
| 实质问题已解决、无新的必须修复项 | 保留当前推荐版，可以提交文案定稿或实际试读 |
| 有改善但关键问题仍在 | 保留有效修改，继续针对那个问题处理 |
| 旧问题解决但产生新问题 | 先修新增问题，不宣称全部完成 |
| 个别改动造成退步 | 回退退步部分，保留有效纠错 |
| 诊断或修法反复失效 | 重新检查审核依据、核心判断与材料缺口 |
| 缺决定性材料 | 指出影响哪项判断，补最少关键材料 |

不能默认最新版最好，也不能自动全退回首稿；选择当前证据支持的最佳版本。
连续两轮仍卡住是重新检查的提醒，不是自动放弃、自动通过或必须达到的轮数。

## 5. 输出与结束

先给当前建议，再用少数原句说明旧问题状态、新问题、版本变化和旧意见的必要修正。
明确比较基线；风格偏好单列为可选，不与必须改混在一起。
没有新增实质问题就直说保留，不自动重写全文，也不要求增加案例、背景或长免责声明。
用户随后要“最终版”，原样返回当前推荐正文及其已要求的结构标记，不另造一次修改。

将文案复审、自我检查、独立复审、事实核验、试读与效果验证分别标明。
同一作者完成修改后的自查不能自称独立复审；多次审核或多个 AI 意见一致也不自动完成事实核验。
独立复审只有实际由未参与改稿的执行者完成、并有记录时才这样称呼；文案通过不证明播放、咨询或成交效果。
问题解决后停止继续润色；未解决项及证据范围如实说明。
