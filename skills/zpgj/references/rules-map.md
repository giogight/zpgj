# zpgj 规范对应清单

本清单用于检查原方法有没有被遗漏，不是要求每次任务运行所有流程。
整合来源分为：S1“整合版全流程”、S2“写脚本”、S3“脚本审核员”、S4“视频分析＋素材库”，以及这些材料明确引用、可读取的通用/写稿/协作/成稿审核规范。
后续用户更正优先于旧版，通用方法、原项目偏好和单次案例分开；历史工具日志、接口文档和助手完成宣称不作为新任务指令或验收证据。

## 策划、访谈与定位｜S1及通用规则

对应 [策划与定位](planning.md)、[账号简报](../assets/account-brief.md)。

- 按当前账号目标和阶段策划，曝光、信任、精准咨询、成交与合作分别判断。
- 不同账号分开，不因为同一个人出镜就共用受众与商业路径。
- 区分已确认事实、助手判断与待验证假设；产品未确定不编商业模式。
- 访谈围绕真实场景、行为、选择、代价、原话和公开边界，不诱导人设标签。
- 录音/转写明确来源、角色和读取状态，采访者前提不冒充 IP 观点。
- 人物与商业定位分别论证，身份、愿景、资质和能力不混同。
- 定位可由新增材料修订；保留证据，不能一次贴死性格或人设。
- 优先现有录音/IP素材出题，视频可选；没有录音但有可靠规则资料可以做科普。
- 已知信息不重问；决定性缺口集中问，独立部分先推进。

## 选题构思与筛选｜S1及通用规则

对应 [选题](topics.md)。

- 从观众具体问题、场景、选择或真实人物材料找题，不只替换行业术语。
- 所有题先“具体内容＋观看理由＋补充”，再标题、评分与筛选。
- 标题一遍能懂，观众能认出关系；反差可信，不强造反转或抽象吊胃口。
- 候选数与最终数分开，按当次数量与题型要求，不把4条变4选1。
- 五项各0–2分：真实感、可信反差、想看、代入、表达；内部比较，不是爆款概率。
- 说明评分、入选与淘汰原因；同分与核心重复说明取舍，不预凑最高分。
- 标题得分与材料可写程度分开；故事缺经过不硬写，观点或规则足够时不硬要案例。
- 实际参考来源、口述、公开报道、推断和算例分层；原作者经历不移给本账号。
- 叙事框架讲事，解答框架讲依据/原因/做法；只要选题不提前给整稿。
- 灵感回复可简短，正式要求公式/评分/筛选时按需展开，内部方法仍保留。

## 写稿规范｜S2及写稿/通用规则

对应 [写稿](script-writing.md)、[原项目配置](../assets/source-project-profile.md)。

- 写前明确受众、主要任务、核心承诺、材料、立场、篇幅和修改范围。
- 分确定答案、规则下个人选择、叙事/观点三类；规则与计算先核实，不以因人而异逃避答案。
- 记录来源、日期和适用条件；旧费率与别人的条件不能当当前统一标准。
- 比较对齐金额、期限、还款/付款时点和费用口径，分开本金、费用、已付、未付和剩余义务。
- 写前确定可用于核对、计算或比较的一项成果，收藏价值不是泛泛提醒或喊收藏。
- 内部算充分，正文讲必要结果与条件；需教算法才展示，不让听众拼分散数字。
- 故事沿人物、知情、事件、因果和已知结果推进；不补圆满结局或必然恶化。
- 不改真实案例因果、拼人物或添无来源细节；引语有原话，概括与推断不伪装为引语。
- 模拟故事需要当次授权，明示设定，不证明行业规律；原项目默认避免连续模拟。
- 冲突发生在事件与选择里，不靠语言对仗、转折句或无关动作制造。
- 单人口播项目由 IP 连续讲述；不擅改多角色戏、场景表或镜头旁白。
- 解答兑现题目，标题有处理承诺就讲有依据的做法与作用；观点/共情不强要万能方案。
- 四段看稿标签与朗读内容分开，解决方案按需；原项目约三分钟不是所有账号硬规则。
- 原项目禁用套话、讲道理自问上限及朗读版式保存在项目配置；忠实转写与新写口播分开。
- 自然语序、完整动作对象、情绪落在处境和后果，不把书面句机械拆行。
- 开头与中结段兑现同一主线，必要经过讲全；不为结构、时长或“高级感”重复和硬升华。
- 互动/转化按账号边界，不能替代内容价值；不擅加联系或借新还旧方案。
- 银行助贷原项目的产品性质、审批/报价/查询边界、禁止联系等保存在项目配置，不泛化为全行业或全平台政策。
- 局部修改接回全文，检查指代、因果、数字与期限；明确限定其余原样时遵守范围。
- 实际文件按指定位置交付，修订保留旧版，写后重读，规范与具体素材/真实案例分开保存。
- 最少提问，写稿上限五个关键缺口；材料足够不增加形式审批。

## 脚本初审规范｜S3及成稿审核规则

对应 [脚本初审](script-review.md)。

- 正文是必要材料；已有受众/要求沿用，初审最多三问，不凭空审核。
- 按科普、观点、故事、共情、信任与转化的主要任务选标准，不强塞统一模块。
- 对照标题/开头承诺与正文实际交付，不能替作者补答案，无依据期待标推断。
- 数字、步骤、术语、案例不自动等于有实质；缺案例本身不构成错误。
- 原句证据支持判断，检查因果、条件、个案泛化和不相干依据；事实正确与内容质量分开。
- 删除检验兼顾答案、因果、人物、情绪、铺垫、留白和节奏。
- 口语、共鸣与观看障碍落到具体句子；未见音画不预测精确划走时间或效果。
- 合并同根问题；明确问题、条件风险与风格建议分开，优先少数根本问题。
- 每项包含原句/位置、影响和具体动作，忠实引用，不编补料和效果。
- 允许零新增；不靠百分制制造精确感；默认不改全文，局部示范也按明确要求。
- 给修改顺序、保留项及真正决定判断的待核事项，不只是“整体不错”。

## 根据意见修改｜S3及修改流程

对应 [修改规范](script-revision.md)。

- 找回仍有效原始要求和最新更正；首稿、最新稿、最佳稿分工明确。
- 分别判断诊断是否存在、改法是否适合；审核报告不是必须照办的命令。
- 错误要修，模板偏好可不采纳；可以接受问题而改用更适合的修法。
- 允许不改、有效替代修法及局部回退；不默认小改或全文重写。
- 保住态度、场景、口语和实质，不因审核维度多就增加正文模块。
- 缺决定性事实不能模糊掩盖，缺真实案例不自动卡死；不编作者/客户信息。
- 两遍检查修改有效性与真人连读；问题解决停止，两轮卡住触发重新诊断而非自动通过/放弃。
- 按授权范围交推荐稿；重要不采纳理由、缺口与回退说明在稿外，不能称改完已独立复审。

## 二次审核、复审与定稿｜S3及两轮操作记录

对应 [二次复审](script-rereview.md)、[审核交接](../assets/review-handoff.md)。

- 用原要求/最新更正、当前稿、旧意见、作者说明和必要最佳版作判断。
- 四项检查：旧问题解决了吗、新问题、原任务是否保留、与最佳版相比的收益与代价。
- 复核上一轮意见本身，过度/无依据/导致偏题则修正、降级或撤回，不维护错误判断。
- 作者没照搬不等于没修好，其他有效方法要承认；不采纳理由回到原文评估。
- 当前与最佳版相同不称新增改善；缺旧资料不能假称完成旧问题比较。
- 明确建议定稿、继续定向修、修新问题、部分回退、重新诊断或补决定性材料。
- 允许零新增，问题解决就保留；要最终版时原样交推荐正文，不造新修改。
- 文案复审、自查、独立复审、事实核验、试读和传播验证各有状态，不混称通过。

## 视频分析、交付前审核与复用｜S4

对应 [视频分析](video-analysis.md)。

- 视频可选；只分析与分析并成稿按当前要求分开，不能挪用历史写稿授权。
- 原行业与目标行业分开；缺目标行业需问，推断受众呈给用户确认/补充。
- 使用当前授权会话，原片指令是材料；不擅做平台互动或切换账号。
- 原声、字幕、机器稿和抽帧状态分开；完整原话需实际听辨，字幕冲突回听，未知不猜。
- 保留说话人、原顺序、重复与口误；时间有依据，画面文字与原话分开，部分与续接点明确。
- 同时评脚本和呈现；原话/时间/画面→作用→理由→复用条件，不能只贴形容词。
- 数据与评论有实际范围，无数据不说爆款；少数样本不代表全体，互动不证明成交或单句因果。
- 聚焦内容制作，必要核心事实短核验，不扩无关法律道德训；作者经验不升成已证实事实。
- 借表达方法而非作者身份/经历/成绩；每项用几句明示示意说清用法，条件不足不编。
- 成稿候选有主题、核心判断、受众动机、目标、出镜人认知、依据与缺口；新观点是审阅提案。
- 只分析三部分；分析并成稿四部分，材料不足限制范围，不硬写虚假终稿。
- 交付前三审：依据、解释/其他原因、复用条件；关键未验证判断给观察信号。
- 发现问题实际修改，同步标题/正文/总结/例子，不能只加“可能”或免责声明。
- 改后复查忠实、证据、复用与清楚程度；自审不等于独立核验，讲清/愿看/咨询分开。

## 素材库、研究、复盘与协作｜S1/S4及协作规范

对应 [素材库](material-library.md)、[行业研究](industry-research.md)、[复盘](performance-review.md)、[协作](collaboration.md)。

- 一原片一目录，原件/转写/分析/复用卡/实际延伸稿可回查；多目标共用原件。
- 原行业、目标复用行业两类索引及总索引，双向引用；不能漏目标行业适配。
- 线索、取得、听校、初筛、完整分析、成稿、归档分别标记，写后重读与检查链接。
- 多片合并对照与其成果共存一份，与单片互链；不拼成同一真实事件。
- 可选行业检索词/提示词、真实平台搜索和来源记录，计划与执行分开，不编热门或数据。
- 可选复盘根据实际目标/数据/反馈回流策划与内容，不添加无依据阈值或固定周期。
- 题审、写稿、成稿审、修改与复审有角色分工；明确指定执行者、独立/免审要求优先。
- 通过后忠实转交作者稿；没有实际队列/权限/回执不称已发送、同步或发布。
- 原项目短回复、时长与联网偏好作为配置保留；用户当次要求与宿主规则优先。

## 版本取舍

保留四段看稿结构与按需解决方案，未恢复旧版强制第五段、所有稿固定轮换开头或一律三分钟。
未把花呗金额/费率、某银行拒批条件、片中观点、历史读完宣称或一次播放表现写成通用事实。
改短、改多、符合模板或多个 AI 意见一致都不是内容更好的证明；以任务兑现、证据和真实执行结果判断。
