# 脚本审核与最小修改建议

用于审核现有短视频稿、判断审核意见，或给出具体修改方向。
默认交付诊断，不直接改写全文；用户明确要求改稿时使用 [修改规范](script-revision.md)，要求二次审核时使用 [二次复审规范](script-rereview.md)。
任务是找出影响这条内容成立的少数问题，同时保留成立的内容与表达。

## 1. 先明确本次审核对象

必需材料是待审正文；没有正文，不凭空审核。
优先从已有信息提取选题、标题、开头、目标观众、本条主要任务及业务边界。
可选材料包括原始来源、作者自述、已确认立场、前版、已有审核报告、画面与字幕。
不重复询问已经提供的背景；只补问会明显改变判断的关键缺口，通常不超过三个。
用户允许直接推进时，列明必要假设，把受其影响的判断标为条件性。
只有文本时，区分文本已能证明的问题与依赖未见素材的风险。
本轮只看指定段落时，检查必要前后文，不自行扩成整个账号诊断。

## 2. 按主要任务选择标准

| 内容任务 | 核心判断 |
| --- | --- |
| 科普、解答 | 是否回答承诺的问题，交代必要解释、判断依据或可用答案。 |
| 观点、讨论 | 立场是否清楚，理由与结论是否对应，分歧是否值得展开。 |
| 故事 | 经历、变化或悬念是否相应展开，事件、因果和人物知情是否接得上。 |
| 共情 | 是否准确呈现目标观众的处境、感受或矛盾。 |
| 信任建立 | 信任是否来自有依据、可理解的判断或行为。 |
| 咨询转化 | 内容是否与目标人群及服务需求衔接，并遵守给定业务边界。 |

这些是审核角度，不是必须加入正文的模块。
混合任务先判断主要任务，检查次要任务是否挤占它。
故事不强求方法清单，共情不强求解决方案，观点不强求唯一答案。
不把行业示例变成行业专用标准，也不为所有稿强加痛点开头、客户案例或推销结尾。
`痛点、冲突、框架、共鸣` 可供看稿，不作为所有内容必须满足的硬性质量标准。

## 3. 对照承诺和实际交付

内部各用一句话概括：

1. 目标观众从选题、标题和开头合理期待获得什么。
2. 正文实际提供了什么。

第二句只依据稿中已有内容，不替作者补出缺失的答案、解释、条件或经过。
观众期待没有明确依据时，标为推测；用户意图与标题形成的期待冲突时，指出具体冲突。
找到兑现承诺的关键原句；没有找到时，说明缺少哪部分。

重点识别：

- 问“为什么”，正文却只提醒“要注意什么”。
- 问“怎样判断”，正文只说“综合考虑、因人而异”。
- 承诺讲经过，正文很快变成泛泛道理。
- 用背景、风险提醒、行动清单或互动引导代替原本要讲清的内容。

上述内容若服务本条承诺可以保留，不因形式相同一律删除。
缩小标题承诺可能是一种方向选择，但不能偷偷换题掩盖原题未回答。

## 4. 判断内容有没有实质

找出正文新增的判断、信息、解释、经历或情绪体验，以及它们对主要任务的作用。
检查必要的原因、过程、条件和判断依据是否已经交代。
听众不应仍需自己补出决定理解或结论的关键一步。
出现数字、步骤、术语或案例，不自动证明内容充实。

- 数字：含义、计算条件、比较口径是否清楚，能否支持后面的判断。
- 步骤：是否是实际动作、判断条件或结果，而非把空话编号。
- 案例：是否展示有关过程，是否用“后来成功了”代替必要解释。
- 观点：理由是否支持立场，是否以抽象态度回避具体矛盾。

解释是否必要由本条承诺决定；只回答一个数字时，不额外强求完整机制课程。
缺案例本身不是问题，已有解释、对比、演示或推理足够时，不要求补案例。
确有缺口时，具体说缺什么事实、条件、因果或经过，不能笼统归为“缺素材”。

## 5. 检查证据与结论

忠实引用原句，检查前提到结论有没有缺环：

- 先后发生被当成因果，可能结果被说成必然。
- 单个经历被扩大成普遍规律，价值选择被说成客观事实。
- 不相干数字、案例或身份被用作结论依据。
- 省略了会改变结论的适用条件，拟议动作被写成已经发生。
- 叙述者知道的信息被直接赋予尚不知情的角色。
- 指代或倒叙转换不清，让听众自行猜主体或时间顺序。

分开记录信息性质与核验状态：公开事实、作者观点、口述经历、模拟或算例、未知。
只有稿件，不能独立确认作者自述真实；没有来源不等于造假，有来源也不等于充分支撑。
模拟只承担说明作用，不作为真实案例或效果证据；用户确认可以表达也不等于事件真实。
新增事实不得靠编人物、对话、心理、金额、客户反应或结局来填缺口。
涉及当前政策、产品或专业规则时，说明具体待核对主张、来源、日期与适用范围。
没有查证不称已核实；没有工具或可靠材料时，保留待核实状态。

数字比较按同一对象口径、期限、时点及成本范围复算；参见写稿参考的数字方法。
区分实际报价与假设金额，区分当下支出、已产生未付成本和剩余义务。
计算成立但用词误导时，只修用词，不无故重建算法或新增费用拆分。
事实、规则与计算核验通过，仍可能偏题、空泛或难懂。
合规判断与内容质量分别说明，不能把“没有发现违规”写成“内容一定好”。

## 6. 检查主线与第一次听的理解

判断每段是否服务本条任务，段落之间有没有必要连接。
删除检验要同时看答案、因果、人物理解、情绪递进、铺垫和节奏。
删掉几乎不影响上述内容时，才考虑删减；不要误删必要承接、留白或强调。

落到具体原句，找出听众可能卡住的原因：

- 抽象表达缺少解释，主语、对象或动作让人猜。
- 前后信息矛盾，关键条件或原因省略。
- 同一意思重复说，没有新增作用。
- 突然转向别的问题，或过度依赖未提供的画面、字幕和背景知识。

“不吸引人、不口语、有 AI 味、没共鸣”必须转成具体问题与影响。
根据已有受众信息判断理解负担，不默认所有观众都是新手。
短句也可能逻辑不成立；语言顺畅也可能没有回答选题。
未见音画时，不把文本推测说成成片事实，不断言观众在精确某秒划走。
可以提出可测试的理解障碍假设，不能预测播放量、咨询或成交。

## 7. 筛选问题，给最小有效改法

先找根本问题，一个问题不要换几个名字重复批评。
区分三种性质：文本可证明的明确问题、依赖未知条件的风险、可选风格建议。
通常指出最影响成立的 1—3 项；零问题就如实说明，重大问题更多时不受数量限制。
优先处理核心错误与承诺缺口，再处理局部理解，最后才谈风格。
每项建议写出动作：删哪段、移到哪里、合并哪处、补哪个指代或因果、缩小哪个结论。
只补必要材料，不因“解释不清”自动增加多个案例、背景段和步骤。
保留已有立场与有效表达；不同意作者价值选择，不足以判定其错误。
不能为迎合审核模板，把故事改成教程、把解答改成故事或把口播改成说明书。

审核报告本身也需要判断：

1. 它指出的问题是否真实存在，有什么原文依据。
2. 它的改法是否适合本条任务，会不会损失原意、风格或必要内容。

诊断正确不代表改法正确，可以接受问题而换一种更合适的修法。
有依据的错误不能以保留风格为由保留；无具体证据的“加强、优化”不构成必须修改。
常规编辑无需反复审批；改变已确认受众、选题、核心立场或承诺时，应确认关键选择。

## 8. 默认输出

先给一句总判断：承诺已兑现、部分兑现、未兑现或信息不足，以及最先处理什么。
只在有实质问题时列出少数诊断，每项包含：

- **原句或位置**：忠实引用，不能把改写句冒充原文。
- **为什么**：说明具体缺环、理解障碍或与本条任务的不匹配。
- **最小改法**：明确操作；用户明确要求局部改写时才给替换示例，不能默默重写全文。

条件性风险与风格建议明确标注，不混成客观错误。
简短说明修改顺序和值得保留的具体内容；不只说“整体不错”。
确有待核实项时，说清核实结果会影响什么，不重复已列问题。
没有明显问题时，建议保留当前稿并进入实际试读，不制造新版本或无依据分数。
文案审核通过不等于事实全核验、试读通过、成片完成或效果得到验证。

## 9. 已授权修改后的复核

二次审核完整流程见 [脚本二次审核与复审](script-rereview.md)，不能只以本节的简要检查代替复审。
对照改动前后，检查实质问题是否解决，是否新增错误或损失原有有效内容。
局部修改必须接回全稿检查指代、衔接、重复、数字与结论，不能只判断改过的段落。
新版更差时撤回退步部分，保留有效纠错，不默认修改越多越好。
反复卡在同一问题时，重新检查诊断、改法、核心判断和决定性材料，不循环换词。
无法解决的关键问题如实说明；没有独立复审，不称已经完成独立复审。
用户只要求改开头时，走写稿参考的快捷路径，不扩大为全文重写。
