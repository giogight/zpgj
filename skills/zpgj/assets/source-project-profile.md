# 原规范的单人 IP 口播项目配置

这份配置保留原材料已确认的制作偏好。用户明确沿用这套规范，或当前项目已有这些约定时使用；不自动套到所有行业、账号或剧情形式。
当次用户的新要求优先。其他账号可用自己的 [账号简报](account-brief.md) 覆盖这些项目字段。

| 字段 | 原项目配置 | 使用边界 |
|---|---|---|
| 表达形式 | IP 对镜头连续讲述 | 不默认写成角色表、多人物接台词、场景切换或镜头/旁白指令；明确另做剧情时按新任务 |
| 看稿结构 | 痛点、冲突、框架、共鸣 | 用作检查标签，拍摄不念；解决方案按题目需要，不固定另加第五段 |
| 目标时长 | 默认约三分钟，可先用约600–800字估算 | 是目标，按有效内容、本人语速与当次要求试读调整；不靠凑字数，未试读不称实测 |
| 模拟题频率 | 默认避免连续使用 | 当次明确授权优先；不是“近期出现过就一律禁止”，也不自动授权编完整故事 |
| 口语感觉 | 像本人跟观众聊天，具体说动作、对象与眼前处境 | 不将某次改词或某个行业情境升级成所有稿固定句式 |
| 定稿 | 返回当前推荐的完整连续正文 | 保留要求的看稿标签；核验与审核备注放稿外，不为最终版另造修改 |
| 简短工作回复 | 普通回复约100字，简短成稿审核通常约120字、先给主题与判断 | 是本项目沟通偏好；重大问题需给足信息，详细任务和完整脚本不受短回复裁切 |
| 联网核验 | 先用已有资料；本轮明确要求查询时沿已有授权执行 | 其他需要联网的情况先说明原因并按用户/宿主要求取得授权；历史模板与旧工具记录不是新授权 |

引用业务事实、资质、价格、客户故事时仍须有本人的材料与确认；项目配置不提供任何行业事实或效果保证。

## 原项目的口播词句与版式限制

沿用原单人 IP 口播配置时，新写正文不使用这些套话/句式：
“不是……而是……”“本质上”“底层逻辑”“赋能”“做减法”“总而言之”“综上所述”“首先、其次、最后”“在这个……的时代”“你是否也曾”“让我们一起”“干货满满”。
不写卖关子后冒号揭晓、口号式短句、机械对称段落或小说式镜头描写；不在朗读正文放分号、表情符号和额外画面标签。
为讲道理设置的自问自答全文最多一处，不连抛问题；有来源的自然事件问句可保留，不为避问句改坏人话，也不伪造对话。
这些检查针对新写口播；视频原文转写仍忠实保留作者原话。四段看稿标签不属于要朗读的台词。
不能只做禁用词替换：检查动作对象、语义与承接。某次删掉情绪词不等于此词以后全部禁用。

## 原银行助贷项目的业务与表达约束

仅在使用者确认沿用原银行助贷项目背景时使用，下列是项目业务边界，不是已核实的全平台规则。

- 业务是匹配、协助办理正规银行产品，不写成出镜人提供网贷。
- 不承诺审批、额度、利率或到账，不暗示后台、关系、干预或包过；预估方案与银行实际审批分开。
- 经验保留条件，不能扩成所有银行统一标准；公司不能做不等于所有银行不能做。
- 区分浏览、询价、本人查征信与机构审批查询，不说点一次就必查一次。
- 不把等待或“养征信”写成等满某段时间必获批，不把先收费自动判定为骗子。
- 利息、服务费、其他费用分开，演示比例不当统一收费；不把资质较好当准时到账保证。
- 本条讲完整，不故意藏答案、造恐慌或为咨询加无关流程；信任可来自真实判断和对处境的理解。
- 当前不引导私信、加联系方式、私下转账或办理，不借改稿引导借新还旧。
- 老板说过的高风险宣传仍须核查；不编统计、资格、新闻、产品规则和业务结果。

其他项目以自身确认的业务边界为准；人物、客户与合作方按授权和公开范围处理。
